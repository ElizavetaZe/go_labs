# Лабораторная работа №8
## Описание задания
В данной лабораторной работе необходимо разработать REST API для управления пользователями:
1. Построение базового REST API (маршруты `/users` и `/users/{id}`).
2. Подключение базы данных PostgreSQL для хранения пользователей.
3. Централизованная обработка ошибок и валидация данных.
4. Пагинация и фильтрация по параметрам запроса.
5. Unit-тесты для каждого маршрута.
6. Документация API.
## Структура проекта
```
main.go       - сервер (задания 1-4)
main_test.go  - тесты (задание 5)
API.md        - документация API (задание 6)
README.md
```
## Инструкция по запуску
Требуется Go 1.22 или новее и установленный PostgreSQL.
1. В константе `dsn` в файле `main.go` указать пароль от PostgreSQL.
2. Один раз установить драйвер: `go get github.com/lib/pq`.
3. Открыть терминал в корне проекта (где находится `go.mod`) и выполнить `go run ./lab8`.
4. Сервер запустится на `http://localhost:8080`. Таблица `users` создаётся автоматически.

Для запуска тестов дополнительно создать тестовую базу (один раз): `CREATE DATABASE lab8_test;`, затем выполнить `go test -v -count=1 ./lab8`.

## Примеры работы программы
Примеры запросов приведены в формате `curl` (в Windows PowerShell использовать `curl.exe`, подробности в `API.md`).

## Задание 1: Базовый REST API
Сервер поддерживает пять маршрутов:

| Метод | Адрес | Описание | Ответ |
|---|---|---|---|
| GET | `/users` | список пользователей | 200 |
| GET | `/users/{id}` | один пользователь | 200 |
| POST | `/users` | добавление | 201 |
| PUT | `/users/{id}` | обновление | 200 |
| DELETE | `/users/{id}` | удаление | 204 |

Данные передаются в формате JSON. Маршрутизация выполняется стандартным `http.HandleFunc` с шаблонами вида `GET /users/{id}`, значение `id` извлекается через `r.PathValue("id")`.
```
curl -X POST http://localhost:8080/users -H "Content-Type: application/json" -d '{"name":"Anna","age":20}'
{"id":1,"name":"Anna","age":20}

curl http://localhost:8080/users/1
{"id":1,"name":"Anna","age":20}
```
## Задание 2: Подключение базы данных
Для хранения пользователей используется PostgreSQL. Подключение выполняется через пакет `database/sql` и драйвер `github.com/lib/pq`. При запуске сервер создаёт таблицу, если её нет:
```sql
CREATE TABLE IF NOT EXISTS users (
    id   SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    age  INT NOT NULL
)
```
Запросы выполняются с параметрами (`$1`, `$2`), что защищает от SQL-инъекций. Данные сохраняются после перезапуска сервера.
## Задание 3: Обработка ошибок и валидация
Обработчики не отвечают на ошибки сами, а возвращают их. Все ошибки превращаются в ответ клиенту в одном месте, в функции-обёртке `handle`:
- ожидаемые ошибки (`AppError`) отправляются клиенту со своим статус-кодом и сообщением;
- неожиданные ошибки (например, недоступна база) записываются в лог сервера, а клиент получает общее сообщение с кодом 500.

Валидация при создании и обновлении: имя не должно быть пустым, возраст должен быть от 1 до 120. Все ошибки возвращаются в формате `{"error": "..."}`.
```
POST /users {"name":"","age":20}       ->  400 {"error":"Имя не может быть пустым"}
POST /users {"name":"Anna","age":200}  ->  400 {"error":"Возраст должен быть от 1 до 120"}
GET /users/999                         ->  404 {"error":"Пользователь не найден"}
GET /users/abc                         ->  400 {"error":"Неверный id"}
```
## Задание 4: Пагинация и фильтрация
Маршрут `GET /users` принимает необязательные параметры запроса:

| Параметр | Описание | По умолчанию |
|---|---|---|
| `name` | поиск по части имени без учёта регистра | без фильтра |
| `age` | пользователи с указанным возрастом | без фильтра |
| `page` | номер страницы | 1 |
| `limit` | записей на странице (1-100) | 10 |

Пагинация реализована через `LIMIT` и `OFFSET` (`offset = (page - 1) * limit`), фильтры через условия `WHERE` в одном SQL-запросе. Параметры можно сочетать. Неверные значения возвращают ошибку 400.
```
curl "http://localhost:8080/users?name=An&age=25&page=1&limit=5"
[{"id":2,"name":"Anton","age":25}]
```
## Задание 5: Тестирование API
Для каждого маршрута написаны тесты на стандартных пакетах `testing` и `net/http/httptest`. Запросы отправляются напрямую в маршрутизатор, без запуска сервера. Тесты работают с отдельной базой `lab8_test` и перед каждым тестом очищают таблицу, поэтому рабочие данные не затрагиваются.

Проверяются разные входные данные:
- `POST /users`: корректные данные, граничные значения возраста (1 и 120), неверный JSON, пустое тело, пустое имя, отсутствие полей, неверный возраст и тип данных;
- `GET /users`: пустой список, фильтры, пагинация, неверные параметры;
- `GET /users/{id}`, `PUT /users/{id}`, `DELETE /users/{id}`: успешная работа, несуществующий пользователь (404), `id` не число (400), неверные данные (400).
