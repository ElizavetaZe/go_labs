# Лабораторная работа №9
## Описание задания
В данной лабораторной работе необходимо разработать консольную клиентскую программу для REST API из лабораторной работы 8:
1. Создание клиентской программы с меню для выполнения CRUD операций.
2. Обработка ответов и ошибок, форматирование и вывод данных.
3. Консольный интерфейс пользователя (добавление, удаление и обновление пользователей).
4. Авторизация: клиент сохраняет токен сессии и передаёт его в заголовках запросов.
5. Поддержка нескольких клиентов, одновременно работающих с сервером.
6. Тестирование и отладка взаимодействия клиента и сервера.
## Структура проекта
```
client.go       - клиентская программа (задания 1-5)
client_test.go  - тесты клиента (задание 6)
README.md
```
Сервер находится в лабораторной работе 9 (папка `lab9/server`). В него добавлен файл `auth.go` с входом (`POST /login`) и проверкой токена.
## Инструкция по запуску
Требуется Go 1.22 или новее и установленный PostgreSQL.
1. Запустить сервер в одном терминале: `go run ./lab9/server`.
2. Запустить клиент в другом терминале: `go run ./lab9`.
3. Для входа в клиенте использовать логин и пароль, заданные на сервере (в примерах ниже `user` и `12345`).

Для запуска тестов клиента сервер и база данных не нужны: `go test -v -count=1 ./lab9`.

## Примеры работы программы
## Задание 1: Создание клиентской программы
Клиент отправляет HTTP-запросы на сервер с помощью `http.NewRequest` и `http.DefaultClient.Do`. Одна функция `request` используется для всех методов (GET, POST, PUT, DELETE). Данные для POST и PUT преобразуются в JSON через `json.Marshal`. Меню позволяет выполнять все CRUD операции:
```
Меню
1. Вывести всех пользователей
2. Вывести пользователя по id
3. Добавить пользователя
4. Обновить пользователя
5. Удалить пользователя
6. Войти
7. Выйти из аккаунта
0. Выход из приложения
```
## Задание 2: Обработка ответов и ошибок
Все ответы сервера обрабатываются в функции `request`, которая различает ситуации:
- сервер недоступен (ошибка при отправке запроса);
- сервер вернул ошибку (код 400 и выше): клиент выводит код и сообщение из ответа `{"error": "..."}`;
- ответ нельзя прочитать или разобрать;
- успешный ответ: JSON разбирается в структуру (`json.Unmarshal`).

Для вывода данных написаны функции `printUser` (один пользователь) и `printUsers` (таблица с выравниванием столбцов).
```
ID    Имя                  Возраст
1     Anna                 21
2     Anton                25
Всего: 2

Ошибка 404: Пользователь не найден
Ошибка 400: Возраст должен быть от 1 до 120
```
## Задание 3: Интерфейс пользователя
Меню работает в цикле до выбора пункта «Выход из приложения». Добавление запрашивает имя и возраст. При обновлении клиент сначала получает текущие данные пользователя и показывает их, а при вводе новых значений пустая строка (Enter) оставляет старое значение. Если введён несуществующий `id`, ошибка появляется сразу.
```
Выберите пункт: 4
Введите id: 1
Текущие данные:
ID:      1
Имя:     Anna
Возраст: 20
Новые данные (Enter - оставить без изменений):
Имя:
Возраст: 21
Пользователь обновлен:
ID:      1
Имя:     Anna
Возраст: 21
```
## Задание 4: Авторизация
Для работы с пользователями нужно войти в аккаунт. Схема работы:
1. Клиент отправляет логин и пароль на `POST /login`.
2. Сервер проверяет их и выдаёт токен (случайную строку).
3. Клиент сохраняет токен в переменной и добавляет заголовок `Authorization: Bearer <токен>` ко всем последующим запросам.
4. Сервер (middleware `requireAuth`) проверяет токен и при его отсутствии или неверном значении отвечает кодом 401.

Выход из аккаунта (пункт 7) очищает токен на клиенте.
```
Выберите пункт: 6
Логин: user
Пароль: 12345
Вход выполнен

Выберите пункт: 6
Логин: user
Пароль: wrong
Ошибка 401: Неверный логин или пароль
```
## Задание 5: Поддержка нескольких клиентов
Клиент можно запустить в нескольких терминалах одновременно. Каждая запущенная копия программы хранит свой токен, поэтому клиенты не мешают друг другу. Все клиенты входят под одним логином и паролем, но при каждом входе сервер выдаёт отдельный токен, и все они действуют одновременно. Сервер обрабатывает каждый запрос в отдельной горутине, список токенов на сервере защищён мьютексом, а данные хранятся в PostgreSQL.

Проверка: запустить клиент в двух-трёх терминалах, войти в каждом, добавить пользователя в первом и вывести список во втором: изменения одного клиента видны остальным.
## Задание 6: Тестирование и отладка
**Автоматические тесты клиента** (`client_test.go`). Тесты запускают тестовый HTTP-сервер (`httptest.NewServer`), который повторяет API лабораторной работы 8 и хранит данные в памяти, и направляют на него клиент. Ввод пользователя подставляется вместо клавиатуры, а вывод программы перехватывается и проверяется. Проверяются все маршруты и функции клиента:

| Тест | Что проверяет |
|---|---|
| `TestRequest` | заголовок `Authorization`, ошибки 401, ответ не JSON, ошибка 500, недоступный сервер |
| `TestErrorMessage` | извлечение текста ошибки из ответа сервера |
| `TestSignIn` | вход (`POST /login`) с неверным и верным паролем, сохранение токена, выход |
| `TestWithoutLogin` | без входа данные не показываются и не изменяются |
| `TestListUsers` | `GET /users`: пустой список и список из двух пользователей |
| `TestShowUser` | `GET /users/{id}`: найден, не найден, `id` не число |
| `TestCreateUser` | `POST /users`: успех, неверный возраст, пустое имя |
| `TestUpdateUser` | `PUT /users/{id}`: успех, пустой ввод оставляет значение, несуществующий пользователь |
| `TestDeleteUser` | `DELETE /users/{id}`: успех, несуществующий пользователь, удаление без входа |

Запуск: `go test -v -count=1 ./lab9`. Все тесты завершаются со статусом `PASS`.
